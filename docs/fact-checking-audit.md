# Аудит правил проверки фактов «Умный туризм»

Срез на **18 октября 2026**. Репозиторий `karat-dev/pay-compass`, ветка `main`. Продукт: Telegram Mini App и бот на Vercel, справочник в JSON, состояние пользователя в Supabase.

Этот документ только описывает правила и предлагает, как их собрать и усилить. Поведение продукта он не меняет: зоны, тексты и пороги показа остаются теми же.

Аудит смотрит, **как устроена проверка**, а не заново открывает сайты банков. Живая правда каждого тарифа здесь не перепроверялась.

## Короткий вывод

Правила зон записаны в `config/trust_config.json` и уже «запечены» в `database/data/countries.json`. Путешественник по умолчанию видит зелёную и жёлтую зоны. Одна шкала свежести 30/60 дней применяется ко всем типам фактов. Для официального источника она почти никогда не убирает факт с экрана: даже очень старый согласованный официальный факт остаётся жёлтым (70 баллов при пороге показа 50).

Собственная проверка владельца принудительно красится в зелёный на 180 дней, даже если по баллам это чёрная зона. Поле `verified_by_us_max_days` в коде не читается, поэтому после 180 дней зона сама не потемнеет.

**78 из 160** карточек, которые страна показывает сразу, не имеют публичной ссылки. Это ровно зелёная и жёлтая зоны страновых карточек (102 + 58).

**Отчёта о неуспешной или незавершённой проверке, который владелец видит сам, сегодня нет.** Перезапуска «все факты / одна страна / один факт» в репозитории нет. Расписания в GitHub Actions и в `vercel.json` нет. Пять внешних проверок ассистента в репозиторий не приходят и зону не меняют.

Файл `VERIFICATION_RULES.md`, на который ссылается `countries.json` (`rules_ref`), в репозитории отсутствует. Генератора, который заново считает баллы, в репозитории тоже нет.

## 1. Откуда взяты числа

Считались все карточки `database/data/countries.json`: 6 стран и 7 пошаговых инструкций. Публичная ссылка — та, которую реально отдаёт `database/knowledge_base.py` → `public_source_url` (форум, Telegram и `source_user_facing: false` отбрасываются).

Дата сборки корпуса в файле: `checked_at` = **13.10.2026** у всех 267 карточек. Это штамп пакета, а не дата каждого источника.

Шкала свежести внутри файла сходится с датой расчёта **14.10.2026**: у всех 228 карточек с `score_breakdown` баллы свежести совпали с порогами 30/60 дней (0 расхождений). Проверка: 13.10.2026 в причине записана как «1 день», 15.09.2026 как «29 дней», 16.07.2026 как «90 дней».

Возраст ниже посчитан на **18.10.2026**, то есть через 4 дня после того расчёта. Сами зоны в файле с тех пор не пересчитывались.

Подключённый к этой среде проект Supabase — другая база (таблицы записи к мастерам). Строки `miniapp_fact_reports` и `source_health` боевого проекта отсюда не читались. Вывод про отчёты сделан по коду и миграциям.

## 2. Как устроены правила сейчас

### 2.1. Шкала в `config/trust_config.json`

Баллы источника:

| Тип | Баллы |
|---|---|
| official | 50 |
| media | 30 |
| отзыв путешественника | 15 за отчёт, потолок 30 |
| internal (наш опыт, репозиторий без публичной ссылки) | 0 |

Свежесть по `date_verified` относительно даты расчёта:

| Возраст | Баллы |
|---|---|
| до 30 дней включительно | 30 |
| 31–60 дней | 15 |
| старше, или даты нет | 0 |

Пометка `date_estimated: true` баллы не обнуляет, если дата всё же проставлена. В причине это пишется как «дата оценочная», а 30 или 15 баллов всё равно начисляются.

Согласованность: `agree` = 20, `conflict` = 0.

Зона по сумме:

| Зона | Минимум | Что видит путешественник |
|---|---|---|
| green | 75 | сразу, статус `confirmed` |
| yellow | 50 | сразу, статус `unconfirmed` |
| red | 25 | за кнопкой «Показать непроверенное» |
| black | 0 | за той же кнопкой, статус `outdated_or_refuted` |

Порог показа задаёт `display.default_min` = 50. Поэтому на экране по умолчанию зелёное и жёлтое. Дополнительно прячется зона `advice-unsupported`. Пробел `gap` показывается всегда с подписью «не исследовано».

Отдельные принудительные зоны (применены при сборке JSON, в рантайме заново не считаются):

| Правило | Куда ставит | Срок |
|---|---|---|
| `refuted: true` | black | без срока |
| `contradicted_by_own: true` | не выше red | без срока |
| `verified_by_us: true` | green | `verified_by_us_max_days` = 180, поле кодом не читается |
| совет (`advice`) | худшая зона из опор; балла нет | если опоры нет — `advice-unsupported` и карточка скрыта |
| пробел (`gap`) | `gap`, балла нет | подпись «не исследовано» |

Максимум шкалы: официальный источник 50 + свежесть 30 + согласие 20 = 100.

Что из этого читает работающее приложение:

- пороги зон и `display.default_min` — да, чтобы решить, прятать ли карточку;
- подпись пробела — да;
- `source_points`, `freshness_points`, `agreement_points`, `refuted_zone`, `verified_by_us_zone`, `verified_by_us_max_days`, `contradicted_by_own_zone`, `zone_to_status`, `repo_report_date`, `recent_traveler_date` — лежат в конфиге и **в расчёте при запросе не участвуют**.

Зона берётся готовой из JSON. Старение после 14.10.2026 само на экран не влияет.

На карточке путешественник видит текст, дату («Проверено: …», для скрытых — «Непроверено») и ссылку либо фразу «Официальной ссылки нет». Баллы, разбивка, `reason`, `unknown_zone`, `decision_needed`, `needs_owner_check`, `agreement`, `refuted`, `verified_by_us` в каталог не попадают (`database/miniapp_catalog.py`). Пометка `display_note` тоже не показывается.

Легенда на входе говорит, что зелёный — это официальный источник или личный опыт. На самой карточке «наш опыт» не подписан: у таких фактов просто нет ссылки.

### 2.3. Две другие шкалы, которые живут рядом

1. Скрейперы пишут в таблицу `sources` свои `trust_score`: официальный банк 10, форум AWD 8, СМИ 7, Telegram 3. Это не баллы 50/30/15 из `trust_config.json`. На зону карточки они не влияют.
2. Если у страны нет справочника в JSON, старый обработчик бота показывает заготовку из `CountryRepository.get_country_summary`: UnionPay «1,5–2,5%», карты «Мир», наличные, с уверенностью 95–100% и датами 10–13.09.2026. В списке запуска есть Казахстан, Армения и Египет, справочника по ним нет. Mini App эти три страны не отдаёт. Старый callback бота — отдаёт, если страна есть в таблице `countries`. Заготовка помечена как проверенная, хотя через шкалу зон она не проходила.

## 5. Достаточно ли этого для большого продукта

Для шести стран и ручной сборки шкала уже делает полезную вещь: прячет красное и чёрное, не выдаёт пробел за проверенный факт и не тащит форум в текст. Для продукта, который будет расти по странам и по часто меняющимся тарифам, этого мало. Конкретно:

1. **Одна свежесть на все факты.** Лимит банка и комиссия QR меняются чаще, чем норма tax free или правило въезда. Сейчас и то и другое живёт на порогах 30 и 60 дней. Официальный источник при согласии не падает ниже 70, то есть жёлтая зона и экран по умолчанию — навсегда, пока человек не пересоберёт файл. Виза в файле маршрута не стареет вообще: у неё нет даты.

2. **Порог 30 дней уже пробит, экран об этом не знает.** Unired на 18.10.2026 по собственной формуле должен быть красным и спрятанным. Он жёлтый и видимый, при внутреннем запрете рекомендовать.

3. **Свой опыт красится зелёным сильнее, чем шкала.** 10 карточек с 20 баллами (чёрная зона по цифрам) и 29 карточек с 50 баллами (жёлтая) показаны зелёными. Срок 180 дней в конфиге есть и не исполняется. На карточке не написано «проверено нами», только «официальной ссылки нет». Легенда на входе это частично объясняет, карточка — нет.

4. **Конфликт не равен «убрать с главного экрана».** Он только снимает 20 баллов. Unired с конфликтом набрал 60 и остался жёлтым. Два опровержения в Турции спрятаны правильно, через `refuted`, но вопрос «удалить из продукта?» так и висит внутри файла. Статус «спорно» путешественнику не показывается.

5. **Один источник может быть зелёным.** 101 официальная карточка без второго источника. Два отзыва уже потолок, дальше вес не растёт. Один отзыв может навсегда остаться жёлтым и видимым, если ему меньше 60 дней (15+15+20 = 50).

6. **78 из 160 видимых карточек без публичной ссылки.** Из них 29 зелёных — это свой опыт без подписи на карточке, 3 зелёных — два отзыва без ссылки, 20 — советы, у которых ссылка опоры скрыта, 26 жёлтых фактов — СМИ, «общеизвестно» или один отзыв.

7. **Пробелы подписаны честно, но очереди на них нет.** 11 пробелов и выключенный транспорт Таиланда видны как дыры в содержании. 43 `unknown_zone` и 8 `decision_needed` — дыры в процессе, их не видит даже владелец, пока не откроет JSON.

8. **Журнала по факту нет.** Есть `reason` и `score_breakdown` внутри карточки на момент сборки. Нет истории: кто менял зону, какая проверка прошла, какая упала, какой была прошлая ссылка. `checked_at` у всех 267 карточек одинаковый.

9. **Скрейперы не являются проверкой фактов.** Они складывают сырьё. Разбора `raw_posts` нет. При отсутствии ключей Telegram проверка помечается успешной и сохраняет выдуманные посты. Это опаснее, чем честный сбой.

10. **Маршрут, виза, штампы, цена билета и партнёрские ссылки стоят вне шкалы.** Путешественник видит их рядом со «проверенными» карточками, без зоны и без даты. Заглушки авиакомпаний хотя бы подписаны. Цифры ввоза и визы — нет.

11. **Внешние расписания не замыкаются на продукт.** Пять проверок ассистента и разовое напоминание 20 октября не пишут ни файл, ни issue, ни зону. Для большого продукта это нераспределённая работа: её нельзя повторить из репозитория и нельзя увидеть провал.

12. **Жалоба обещает проверку, которой нет.** Тост «Сохранили. Проверим этот факт» описывает процесс, которого в коде нет.

Этого достаточно как честного черновика справочника на шесть стран. Этого недостаточно как системы, которая сама замечает устаревание и приносит владельцу короткий список «вот это сломалось или мы не смогли проверить».

|---|---|---|---|
| Скрейпер РСХБ или RSS не достучался | Строка `source_health`, лог процесса | Только если сам откроет таблицу или лог запуска | Нет |
| Нет ключей Telethon | В `raw_posts` три выдуманных текста, источник `healthy` | След выглядит как успех | Нет |
| Форум AWD не открылся | Лог, без `source_health` | Нет | Нет |
| Факт старше порога | Ничего, пока никто не пересоберёт JSON | Нет | Нет |
| Конфликт, пробел, `unknown_zone`, `needs_owner_check` | Поля внутри JSON | Нет, кроме пробела на экране путешественника | Уже запечена при сборке |
| Жалоба в Mini App | Строка `miniapp_fact_reports` | Только прямой запрос к Supabase. Уведомления, статуса и админки нет | Нет |
| «Сообщить об ошибке» в старом боте | Событие `error_reported` со slug | Нет | Нет |
| Пять проверок ассистента, напоминание 20.10 | В репозитории следа нет | Только если ассистент написал владельцу у себя | Нет |

Перезапуск, который реально есть:

- `python3 run_scrapers.py` — весь сырой сбор сразу, без страны и без факта, без отчёта в конце.
- Четыре workflow с `workflow_dispatch`: миграции Supabase и два диагностических вызова Telegram (`getMe`, `getWebhookInfo`). К фактам они не относятся.
- Правка `countries.json` руками и деплой. Это и есть сегодняшняя «перепроверка».

Каталог на Vercel перечитывает JSON при сборке функции. Отдельной команды «пересчитать зоны» нет.

## 7. Предлагаемые правила

Принцип, который не ослабляется: **непроверенное не показывается как проверенное.** Пробел остаётся «не исследовано». Конфликт не красится в зелёный и не остаётся на экране по умолчанию. Свой опыт подписывается «проверено нами» и датой, а не выглядит как официальная страница. Один отзыв не даёт зелёный. Нет публичной ссылки — нет зелёного, кроме явно подписанного своего опыта. Сбой проверки не повышает зону. Молчание проверки не значит «всё хорошо».

Ниже правила, которые имеет смысл принять. Это предложение, не текущее поведение. Блок 7.0 владелец уже принял: он перекрывает черновик там, где они расходятся.

### 7.0. Принятые решения владельца (18.10.2026)

Направление аудита принято. Три решения уже фиксированы. Классы свежести из раздела 7.1 пока нет.

**Куда класть отчёт.** Короткое сообщение — в Telegram владельцу через бота `@TravelPaymentsGuideBot`, чат `303653591`. Тот же текст попадает в сводку GitHub Actions и в артефакт прогона. Секрет токена — `TELEGRAM_BOT_TOKEN` (то же имя, что у бота на Vercel и в остальных workflow). Чат задаётся секретом `OWNER_TELEGRAM_CHAT_ID`; если секрета нет, берётся `303653591`. Если токена в Actions нет, прогон отчёта не падает: отправка пропускается, в сводке написано, какой секрет добавить. Рядом с человеческим текстом лежит машинный `fact_check_report.json`, чтобы помощник мог действовать по фактам, а не по абзацу.

**Понижение и повышение.** Скрипт отчёта данные не меняет. Поле `automatic: true` у действия значит, что помощник может применить его без повторного вопроса владельцу.

| Действие | Когда само | Когда только вопрос владельцу |
|---|---|---|
| Понизить зону (`downgrade`) | Всегда, если записанная зона выше зоны по формуле на сегодня | — |
| Поднять до жёлтого (`upgrade_candidate`, `upgrade_to: yellow`) | Есть не меньше 3 независимых свежих подтверждений: разные люди или разные площадки. Перепечатка одного источника считается одним | Счётчик отзывов без списка людей и площадок. Такое число само по себе жёлтый не включает |
| Поднять до зелёного (`upgrade_candidate`, `upgrade_to: green`) | Официальная страница банка, оператора или ведомства открылась и подтверждает формулировку факта | Зелёный только из отзывов путешественников, сколько бы их ни было. Отзывы не задают вопрос «поднять до зелёного» и не красят зону в зелёный |

Свежее подтверждение — не старше верхней планки свежести из `trust_config.json` (сейчас 30 дней). Открытие страницы (HTTP 2xx) само по себе не «подтверждает» текст: пока проверка не сверила формулировку со страницей, автоматический зелёный не предлагается.

### 7.1. Классы по тому, как быстро факт портится

| Класс | Что входит | Как часто проверять | Зелёный | Жёлтый | Красный и ниже |
|---|---|---|---|---|---|
| Быстрый | Лимиты и тарифы карт, «QR работает / не работает», комиссия банкомата, курс пополнения кошелька | раз в 7 дней | Официальная страница моложе 14 дней, без конфликта. Либо свой платёж моложе 14 дней, на карточке написано «проверено нами» | Один официальный источник моложе 30 дней, либо два независимых отзыва моложе 14 дней. Один отзыв жёлтым не становится | Старше порога класса, конфликт, источник не открылся, один отзыв |
| Средний | Открытие местной карты, транспортная карта, норма по наличным, жива ли партнёрская ссылка | раз в 30 дней | Официальная страница или свой визит моложе 90 дней, без конфликта, свой визит подписан | Один нормальный источник моложе 180 дней | Старше, конфликт, ссылка не открывается |
| Медленный | Виза и срок въезда, штампы, законный tax free, общие нормы 115-ФЗ | раз в 90 дней и сразу при новости | Страница ведомства моложе 365 дней | Вторичный источник, на карточке это сказано | Нет страницы ведомства, новость противоречит тексту |
| Цена | Снимок авиацены, сверка Aviasales | снимок раз в 7 дней, сверка с живой ценой раз в 30 дней | Цена не бывает «проверенным фактом». На экране только «снимок на дату и время» | — | Расхождение снимка и живой цены больше порога, который задаст владелец, — в отчёт. На экране цена не появляется |
| Ссылка | Партнёрские URL | раз в 7 дней, HEAD или GET | Открывается и `erid` на месте. Это исправность ссылки, не правда оффера | — | Не открылась — кнопка скрыта, строка в отчёте |

Глобальные 30/60 дней остаются только как запасной класс, пока факт не разнесён по таблице выше. Новый факт без класса не получает зелёный.

Свой опыт в быстром классе живёт 14 дней, не 180. 180 дней можно оставить медленному классу, если владелец так решит. После срока зона падает сама: свой опыт без свежей даты уходит из зелёного в красный, а не зависает.

### 7.2. Источники и конфликты

| Ситуация | Правило |
|---|---|
| Один официальный URL | Зелёный только в своём классе и только пока дата свежая. В карточке видна ссылка |
| Один отзыв | Не выше красного. В жёлтый и зелёный не попадает |
| Два отзыва, которые говорят одно и то же | Сами жёлтый не включают: для автоматического жёлтого нужно 3 независимых свежих подтверждения (раздел 7.0). Зелёный из отзывов не ставится |
| Отзывы спорят или спорят с нашим визитом | Не выше красного. На карточке короткая фраза «данные расходятся», без выбора «правильной» стороны |
| Опровержение | Чёрный, скрыт, в отчёте владельцу строка «убрать или переписать» |
| Нет публичной ссылки и это не подписанный свой опыт | Не выше красного |
| «Общеизвестно», блог, коммерческий пересказ | Не official. Потолок — media, и только если есть URL |
| Пробел | Зона `gap`, текст «не исследовано», в ежемесячный отчёт покрытия |
| Совет | Зона худшей опоры. Нет опоры — карточка скрыта, в продукт не выходит |
| Виза, штамп, риск маршрута | Те же карточки, что и оплата. Отдельный текст маршрута без зоны не публикуется |

Десять перепечаток одного поста не дают ни жёлтый, ни зелёный. Много разных отзывов тоже не делают факт зелёным сами: вопрос владельцу «поднять до зелёного» снят, зона отзывов ограничена жёлтым. Жёлтый сам ставится только при трёх независимых свежих подтверждениях. Это принятое правило 7.0, оно важнее черновой фразы «два отзыва уже жёлтый».

### 7.3. Что считать сбоем

| Итог проверки | Зона | Отчёт владельцу |
|---|---|---|
| Совпало с источником, дата свежая, класс позволяет | остаётся или поднимается только если выполнены правила класса | в сводку как «сошлось», без шума |
| Источник открылся и текст больше не совпадает | вниз на одну зону сразу, не ниже красного до решения владельца | строка fail |
| Источник не открылся, таймаут, капча | зона не повышается. Повтор на следующий прогон. Второй провал подряд — вниз на одну зону | строка fail или inconclusive, второе явно помечено |
| Не смогли сравнить (нет парсера, нет даты, страница про тариф молчит) | зона не повышается | строка inconclusive, не прячется в «успех» |
| Нет ключей к Telegram | прогон этого источника = inconclusive. Выдуманные посты не пишутся, `healthy` не ставится | строка inconclusive |
| Жалоба путешественника | зона сразу не прыгает. Жалоба попадает в тот же отчёт, факту ставится «есть жалоба» | строка, пока человек не закроет |

Молчаливый прогон, после которого файл не изменился, не считается успехом. В отчёте есть число «проверено / сошлось / не сошлось / не смогли проверить».

### 7.4. Формат отчёта владельцу

Один отчёт на прогон. Канал принят в разделе 7.0: Telegram владельцу, сводка и артефакт GitHub Actions, плюс `fact_check_report.json`. Состав человеческой сводки:

- когда, какой scope (`all`, страна, категория, один факт), какой класс;
- сколько карточек в scope, сколько сошлось, не сошлось, не смогли проверить, пропущено;
- по каждой проблеме: id факта, страна, раздел, класс, текущая зона, зона по правилу, возраст, URL, с чем сравнивали, одно предложение почему;
- отдельно блок «решения владельца» — бывший `decision_needed`;
- отдельно «не исследовано» — список пробелов;
- жалобы из `miniapp_fact_reports` с прошлого отчёта, без текста длиннее одной строки в сводке.

Отчёт не содержит новых «проверенных» формулировок. Он говорит, что старая карточка не подтвердилась или что проверить не вышло.

### 7.5. Как перезапускать

Один workflow `workflow_dispatch`, имя по смыслу fact-check. Входы:

| Вход | Значения |
|---|---|
| scope | `all`, `country`, `category`, `fact` |
| country | slug, если scope = country |
| category | класс или раздел справочника |
| fact_id | стабильный id каталога, если scope = fact |
| apply | по умолчанию `report`. Запись новых зон в JSON — отдельный шаг и только после решения владельца |

Выход прогона — сводка в Telegram и артефакт workflow (текст и JSON), не коммит в репозиторий. Issue как единственный канал больше не нужен: владелец выбрал Telegram (раздел 7.0).

По расписанию workflow вызывает тот же код со scope, который совпадает с классом: понедельник — быстрый класс и снимок цен, 3-е число — медленный класс (виза, штампы), 7-е число — сверка цены, если появится кэш. Внешние проверки ассистента либо заменяются этим workflow, либо ассистент в конце пишет в тот же формат issue. Второй тихий канал не оставляем.

Жалоба из Mini App открывает ту же форму отчёта на один `fact_id`, а не только строку в таблице.

Тост пользователю меняется на честное «Сохранили сообщение» в том шаге, где появится реальная очередь. Пока очереди нет, текст обещания лучше убрать. Это уже смена поведения, поэтому в этот аудит не входит.
