# Отчёт проверки фактов

Скрипт `scripts/fact_check_report.py` читает `database/data/countries.json` и `config/trust_config.json` и печатает отчёт. Он не меняет справочник, конфиг и базу.

Зона, которую видит путешественник, считается при выдаче в мини-приложении, API и боте. Считает её `database/trust_zones.py` — тот же модуль, что и этот отчёт. Записанное поле `zone` только вход: его не показывают вслепую и этот прогон его не переписывает.

«Автоматически» значит: помощник владельца может выполнить предложенное действие без повторного вопроса. Сам прогон файл не переписывает.

Прогон: вручную в GitHub Actions, каждый понедельник в 09:00 по Москве (`0 6 * * 1` UTC) и при push в `main` файлов `database/data/countries.json` или `config/trust_config.json`. Расписание и push не передают inputs: охват тогда весь справочник. Даты следующих автопроверок читаются из `auto_checks` в конфиге: еженедельная проверка фактов, трансферы 10-го числа, правила въезда 3-го, сверка кэша 7-го. В коде этих чисел нет. GitHub Actions запускает только еженедельный прогон; остальные даты отчёт показывает, но сам по ним не ходит.

Все сроки, баллы, длины классов, порог «проверено нами», число подтверждений для жёлтого и доля раннего предупреждения читаются из `config/trust_config.json`. В коде проверки фактов этих чисел нет.

## Живая зона

На дату выдачи (`date.today()` в приложении, `--as-of` в отчёте):

1. Баллы источника, свежести и согласия — из `source_points`, `freshness_points`, `agreement_points`.
2. Класс изменчивости — явное поле `volatility_class`, иначе раздел, подраздел или инструкция из `volatility`. Класс `fallback` не может быть зелёным.
3. `verified_by_us` держит зелёный только пока возраст не больше `verified_by_us_max_days` и не больше `green_max_days` класса. Сейчас предел «проверено нами» — 90 дней.
4. Понижение относительно записанной зоны автоматическое.
5. Повышение — только по правилу ниже. Без него живая зона не выше записанной.

`computed_zone` в JSON — эта живая зона. `score_zone` — зона одних баллов, без надбавки «проверено нами».

## Правило повышения и понижения

Принято владельцем 18.10.2026. Та же формулировка лежит в черновике аудита, раздел 7.0 файла `docs/fact-checking-audit.md`. Пока тот черновик не влит в main, рабочая копия правила — этот раздел.

| Действие | Когда | Поле в JSON |
| --- | --- | --- |
| Понизить | Записанная зона выше живой зоны | `suggested_action: downgrade`, `automatic: true` |
| Поднять до жёлтого | Не меньше `upgrade.yellow_min_independent_confirmations` независимых свежих подтверждений: разные люди или разные площадки. Перепечатка одного источника — одно подтверждение. Голое поле `reports` независимость не доказывает | `upgrade_candidate`, `upgrade_to: yellow`, `automatic: true` |
| Поднять до зелёного в выдаче | В факте стоит `official_confirmed` и страница банка, оператора или ведомства есть в источнике, согласие максимальное, формула зелёная | живая зона становится зелёной |
| Поднять до зелёного в отчёте | Страница банка, оператора или ведомства открылась и сверка текста разрешена (`content_confirmed: true`). Выдача сама по HTTP не ходит и 2xx подтверждением текста не считает | `upgrade_candidate`, `upgrade_to: green`, `automatic: true` |
| Зелёный только из отзывов | Формула даёт зелёный, а источник — отзывы | зона не выше `traveler_unapproved_max_zone`, `owner_prompt` остаётся `null` |

Свежее подтверждение — не старше `fresh_days` класса (у запасного класса — окно класса). HTTP 2xx без сверки текста зелёный не включает: действие будет `owner_manual_check`. Пока HTTP в прогоне выключен, для такого факта действие `rerun`.

Список банков, операторов и доменов `.gov` / `.go.th` / `.go.jp` — `official_publishers` в конфиге.

Отзывы не ставят зелёный и не спрашивают владельца, поднимать ли его. Если в файле зелёный держится только на отзывах, живая зона ограничена `traveler_unapproved_max_zone`.

## Раннее предупреждение

Кроме живой зоны для каждого посчитанного факта есть следующая более низкая зона и дата, когда свежесть или окно класса её уронит.

`at_risk` истинен, если выполняется хотя бы одно условие из `early_warning`:

- до этого снижения осталось меньше `share` окна класса (сейчас 0.25);
- согласие равно `conflict_agreement`;
- счётчик `source_failure_field` не меньше `source_failure_min_count`, либо источник один раз уже не открылся.

В тексте отчёта раздел «Скоро съедут»: идентификатор, живая зона, следующая зона, дата снижения, причина. Для такого факта `suggested_action` — `refresh_search`, чтобы недельный разбор успел заново поискать источник. То же действие ставится, если в данных факта `refresh_search: true`: это заявление владельца без страницы оператора или СМИ, и свой ли это опыт, ещё не подтверждено. Если действие уже `downgrade` или `upgrade_candidate`, оно не подменяется: понижение важнее, а факт всё равно попадает в раздел «Скоро съедут», когда `at_risk`.

## Сводка

Человеческий текст на русском. Счётчики:

- проверено — все карточки в охвате;
- сошлось — записанная зона равна живой, баллы её держат;
- не сошлось — записанная зона и живая различаются;
- устарело — живая зона та же, но баллы уже слабее записанной или свежесть в файле не совпала с пересчётом;
- не смогли проверить — пробел, совет или нет данных для формулы;
- нужно решение владельца — карточки с пометкой `decision_needed`;
- скоро съедут — карточки с `at_risk`;
- обновить поиск источника — карточки с `suggested_action: refresh_search`.

У каждого факта есть `next_auto_check`: дата следующей автопроверки, которая покрывает его класс. Расписание берётся из `auto_checks.schedules`. Более узкое расписание с `categories` важнее общего по классу: виза и штампы (`visa`, `stamps`, класс `slow`) — 3-е число, билеты (`tickets`) — 7-е, трансферы — 10-е, класс `bank_procedure` вместе с `fast`, `medium`, `slow` и `fallback` — ближайший понедельник после даты расчёта. Список классов понедельника лежит в `auto_checks.schedules`, не в коде. Если факт `at_risk` и `drops_on` раньше этой даты, следующая автопроверка — `drops_on`. Если по логике автопроверки нет, `next_auto_check` равен `null`, а `owner_question_type` — `product` или `logic`. В тексте это «Нет автопроверки — нужен твой ответ (продуктовый)» или «(логический)». Продуктовый вопрос — свой опыт, зелёный только из отзывов, конфликт, ручная проверка или решение владельца. Логический — пробел, формула без источника, который автопроверка умеет открыть, или класс вне расписаний. Сводка и Telegram по справочнику и по блоку трансферов отдельно считают факты на каждую дату, сколько вопросов каждого типа и разбивку по причине из `reason_labels` (свой опыт, отзывы, конфликт, пробел и остальные). Причина — первое совпавшее правило.

Отдельный блок «Трансферы и маршруты» считает измерения маршрута с `transfer_topic`: время между аэропортами и до города, общественный транспорт, такси и цена трансфера. Класс свежести берётся из `volatility.transfer_measures`: время в пути — `transfer_travel_time` (те же окна, что у `slow`), цена, такси, интервал и расписание — `transfer_price_schedule` (те же окна, что у `medium`). В блоке: счётчики по живой зоне, «Скоро съедут» (`at_risk`), «Устарело» (свежесть на открытой полосе `freshness_points`) и оставшиеся «не исследовано». Эти карточки не входят в сводку справочника. Оценки карт (`source_kinds.map_estimate`) тоже входят в блок. В формулу «закладывайте N» они попадают только если `route_rules.allow_map_estimate_in_allowance` включён; по умолчанию выключен, и без минимальной стыковки совет остаётся «не исследовано». Те же счётчики уходят в Telegram. Push измерений `database/data/route_model/` тоже запускает прогон.

Раздел «Ручные проверки владельца» нумерует карточки с `needs_owner_check`.

## Схема JSON

`schema_version`: **1**. Файл пишется только если передан `--json`. Новые поля версии 1 добавляются, старые не переименовываются.

Корень:

| Поле | Смысл |
| --- | --- |
| `schema_version` | `1` |
| `generated_at` | Время сборки, ISO 8601 со смещением |
| `as_of` | Дата, на которую считается свежесть, `YYYY-MM-DD` |
| `scope` | `all` или `country` |
| `country` | Slug или `null` |
| `scope_label` | Подпись охвата |
| `http_checked` | Был ли запрошен обход ссылок |
| `rules` | Путь `config/trust_config.json` |
| `upgrade_rule` | Порог жёлтого, доля раннего предупреждения, действие `refresh_search` |
| `summary` | Счётчики, включая `at_risk` и `refresh_search` |
| `facts` | Одна запись на карточку |
| `auto_check` | Счётчики следующей автопроверки по справочнику: даты и вопросы владельцу |

Карточка:

| Поле | Смысл |
| --- | --- |
| `fact_id` | Тот же идентификатор, что в мини-приложении: `{scope}:{sha256(scope + перевод строки + text)[:16]}` |
| `country` | Slug страны |
| `category` | Раздел: checklist, pay_on_site, wallets, local_card, cash, atms, transport, risks, tax_free |
| `instruction_id` | Идентификатор инструкции или `null` |
| `text` | Текст карточки |
| `current_zone` | Зона в файле |
| `computed_zone` | Живая зона на `as_of`. У пробела и совета `null` |
| `score_zone` | Зона одних баллов, без надбавки «проверено нами» |
| `score` | Сумма баллов или `null` |
| `status` | `ok`, `fail`, `stale`, `inconclusive` |
| `reason` | Почему такое действие |
| `source_urls` | HTTP-ссылки из поля `source` |
| `public_source_url` | Ссылка, которую можно показать путешественнику, или `null` |
| `http_results` | См. ниже. Пусто, если HTTP выключен |
| `last_check_date` | `date_verified` или `checked_at`, `YYYY-MM-DD` |
| `suggested_action` | Одно из значений ниже или `null`, если делать нечего |
| `automatic` | Помощник может выполнить действие без нового вопроса |
| `upgrade_to` | `yellow`, `green` или `null` |
| `owner_prompt` | Всегда `null`. Путь «отзывы → вопрос владельцу → зелёный» снят |
| `next_zone` | Следующая более низкая зона по сроку свежести или окна класса, либо `null` |
| `drops_on` | Дата этого снижения, `YYYY-MM-DD`, либо `null` |
| `at_risk` | Факт в раннем предупреждении |
| `at_risk_reason` | Причины из `early_warning.reasons`, через «; », либо `null` |
| `next_auto_check` | Дата следующей автопроверки, `YYYY-MM-DD`, либо `null` |
| `owner_question_type` | `product`, `logic` или `null`, если дата есть |
| `owner_question_reason` | Ключ из `auto_checks.reason_labels`, либо `null` |
| `auto_check_text` | Дата или фраза «Нет автопроверки — нужен твой ответ (…)» |
| `flags` | Служебные метки, отсортированы |

`suggested_action`:

| Значение | Смысл |
| --- | --- |
| `downgrade` | Понизить записанную зону до `computed_zone` |
| `fix_link` | Ссылка отсутствует на видимой карточке или отвечает кодом из `http.broken_statuses` |
| `upgrade_candidate` | Кандидат на повышение. Куда — в `upgrade_to` |
| `refresh_search` | До снижения (`at_risk`) или заявление владельца с полем `refresh_search` без страницы оператора или СМИ: заново поискать подтверждение |
| `rerun` | Повторить прогон: нет HTTP, таймаут, повторный статус |
| `owner_decision` | Нужен ответ владельца. Текст вопроса в `reason` или `owner_prompt` |
| `owner_manual_check` | Открыть источник или свою заметку руками |
| `null` | Зона сходится, отдельного шага нет |

`http_results[]`: `url`, `status_code`, `error`, `content_confirmed`. Обычный загрузчик всегда ставит `content_confirmed: false`: он только открывает страницу и читает начало ответа. Сверка формулировки в этот прогон не входит. Коды из `http.failure_exclude_statuses` — блок, не битая ссылка.

`summary`: `checked`, `confirmed`, `not_confirmed`, `stale`, `could_not_check`, `needs_owner_decision`, `needs_owner_manual_check`, `gaps`, `unknown_zone`, `no_public_source`, `green_prompts`, `at_risk`, `refresh_search`.

Поля `at_risk`, `next_zone`, `drops_on` и `stored_zone` в публичный каталог мини-приложения не попадают. Идентификатор и набор полей версии 1 не переименовываются. Новое поле можно добавить. Ломающее изменение — новая `schema_version`.

## Telegram

После отчёта workflow вызывает `sendMessage` бота @TravelPaymentsGuideBot.

- Токен: секрет **`TELEGRAM_BOT_TOKEN`**. Это тот же секрет, что у бота. `BOT_TOKEN` не используется: в настройках он по умолчанию заглушка.
- Чат: секрет **`OWNER_TELEGRAM_CHAT_ID`**. Если секрета нет, чат `303653591`.
- Секрета токена нет — задание не падает. В сводку пишется, что нужно добавить `TELEGRAM_BOT_TOKEN` в Settings → Secrets and variables → Actions.
- Сообщение короче 4096 символов. Длинный текст режется, ссылка на прогон остаётся.
- Ссылка на прогон берётся из `GITHUB_SERVER_URL`, `GITHUB_REPOSITORY`, `GITHUB_RUN_ID`.

## Запуск локально

```bash
python3 scripts/fact_check_report.py --as-of 2026-10-18 --no-http
python3 scripts/fact_check_report.py --scope country --country georgia --json fact_check_report.json --text fact_check_report.txt
```

`--http` по умолчанию выключен. В workflow он включён. `--send-telegram` шлёт сообщение, только если задан `TELEGRAM_BOT_TOKEN`.
